Header - Program Manager selector does not change the view to an alternate role.

User Roles should be applied to a User.   When a Impersonation role is selected  the Header should change to the role and only the  features visible to that role should be visible.  The selected role should appear under the assigned users name. 

The Left Navigation window displays the logged in user name. That name should reflect the signed in user.

Admin Users can set the interface role view for any system role.  The impersonated/active role name is always shown in the top header bar underneath the user name.

The User Profile card under Security and Access should contain a list of the program roles assigned to that user. An Admin user can set additional roles for a user.

There needs to be a Roles capability configuration checklist matrix under the Security and Access Section.   the configuration Matrix contains each section and feature available in the system. each section feature configuration specifies CRUD operations for the user role.
These user roles / configurations are applied by default to each user as a group.  If finer grained groups are needed then versions of that group are defined and permissions applied to the group. 

The user Roles matrix drives what is visible for a user.
