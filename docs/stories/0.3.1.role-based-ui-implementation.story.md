# Story 0.3.1: Role-Based UI Implementation with User Impersonation

## Status
✅ **COMPLETED** - October 9, 2025

**Implementation Summary:** `/docs/implementation-summary-story-0.3.1.md`

## Story
**As a** Admin User,
**I want** to view and interact with the system from the perspective of any user role through role impersonation controls,
**so that** I can test role-specific permissions, validate UI visibility for each role, and provide effective user support without compromising security.

## Acceptance Criteria
1. Header displays a role selector dropdown for Admin users that allows selection of any system role for impersonation
2. When a role is selected for impersonation, the selected role name appears underneath the logged-in user's name in the header
3. The left navigation sidebar displays only the menu items and features visible to the currently impersonated/active role
4. All UI elements (buttons, tabs, sections) are filtered based on the impersonated role's permissions as defined in the roles-feature-matrix
5. The logged-in user's actual username remains visible in the navigation sidebar
6. The User Profile card under Security and Access displays a list of all program roles assigned to each user
7. Admin users can assign additional roles to users from the User Profile card
8. A comprehensive Roles Capability Configuration Matrix is accessible under the Security and Access section
9. The configuration matrix displays all system sections and features with CRUD operation permissions for each user role
10. Role configurations can be applied to users as groups with support for fine-grained permission variations
11. Impersonation state persists during the user session but is clearly indicated to prevent confusion
12. Admin users can exit impersonation mode and return to their admin view at any time

## Dev Notes

### Epic Context
This story (0.3.1) is part of Epic 0: User Account and Role Management. It builds on the foundational role assignment and access control work from Story 0.1.3, implementing the UI layer for role-based permissions and admin impersonation capabilities. This story provides the visual interface and user experience for the comprehensive role-based access control system defined in the roles-feature-matrix specification.

### Technology Stack Context
[Source: docs/technical/tech-stack.md]
- **Frontend:** React 18 with TypeScript, Vite build tooling
- **UI Components:** shadcn/ui component library with Tailwind CSS
- **State Management:** React Context API for role/impersonation state
- **Backend:** Fastify framework with TypeScript
- **Database:** PostgreSQL 16 with Prisma ORM
- **Authentication:** Keycloak integration with JWT tokens

### Data Models
[Source: docs/technical/specifications/roles-feature-matrix.md]
- **User Role Assignments:**
  - User roles: Admin, Gov Program Director, Program Manager, Departing Contractor, Incoming Contractor, Security Officer, Observer, Operational Support
  - Multiple roles can be assigned to a single user
  - Role assignments stored in user_product_assignments table
  - Track role assignment history for audit purposes

- **Impersonation Session:**
  - session_id: UUID reference to user session
  - actual_user_id: UUID of logged-in admin user
  - impersonated_role: String name of role being impersonated
  - started_at: Timestamp of impersonation start
  - ended_at: Nullable timestamp of impersonation end
  - impersonation_reason: Optional text field for audit purposes

### API Specifications
[Source: docs/technical/specifications/security-architecture.md]
- **Role Impersonation Endpoints:**
  - POST /api/security/impersonation/start - Start role impersonation session
    - Request: `{ "role": "Program Manager", "reason": "Testing PM dashboard" }`
    - Response: `{ "success": true, "impersonatedRole": "Program Manager", "sessionId": "uuid" }`
  - POST /api/security/impersonation/end - End current impersonation session
    - Response: `{ "success": true, "restoredRole": "Admin" }`
  - GET /api/security/impersonation/status - Get current impersonation status
    - Response: `{ "isImpersonating": true, "actualRole": "Admin", "impersonatedRole": "Program Manager" }`

- **User Role Management Endpoints:**
  - GET /api/users/:userId/roles - Get all roles assigned to a user
  - POST /api/users/:userId/roles - Assign a new role to a user
  - DELETE /api/users/:userId/roles/:roleId - Remove a role from a user

- **Role Configuration Endpoints:**
  - GET /api/security/roles/matrix - Get complete role capability matrix
  - PUT /api/security/roles/matrix - Update role capability configuration
  - GET /api/security/roles/permissions/:role - Get specific role permissions

[Source: docs/technical/specifications/information-architecture.md#navigation-structure]

Implementation must follow the exact specifications from the roles-feature-matrix document sections 2 (Feature Access Matrix) and 4 (UI Visibility Control). Key navigation patterns:

- **Dashboard:** Visible to all roles with role-specific content

### Security Considerations
[Source: docs/technical/specifications/security-architecture.md]
- **Impersonation Audit Logging:** All impersonation actions must be logged with:
  - Admin user ID
  - Impersonated role
  - Start/end timestamps
  - Reason for impersonation
  - All actions performed during impersonation

- **Session Security:**
  - Impersonation state stored in secure session
  - Cannot impersonate another Admin user
  - Cannot escalate privileges beyond impersonated role
  - Automatic impersonation timeout after 1 hour

- **Permission Validation:**
  - Frontend permission checks for UI visibility
  - Backend permission validation for all API requests
  - Double-check impersonation context in sensitive operations

### UI/UX Guidelines
[Source: docs/technical/specifications/style-guide.md]
- **Role Selector Styling:**
  - Use Primary color (#0A58D0) for impersonation indicator
  - Warning color (#FFC107) for impersonation mode badge
  - Clear visual distinction between actual and impersonated role
  - Minimum touch target size: 44px for mobile

- **Matrix Table Styling:**
  - Use consistent icon set for permission indicators
  - Color coding: Green (full), Yellow (limited), Gray (read-only), Red (no access), Blue (conditional)
  - Responsive table design with horizontal scroll on mobile
  - Sticky header row for large matrices

### Progressive Disclosure
[Source: docs/technical/specifications/frontend-spec.md]
- Role selector only visible to Admin users
- Role assignment interface only shown when viewing user with edit permissions
- Configuration matrix accessible from Security & Access section
- Impersonation mode clearly indicated but not intrusive
- Graceful degradation for users without role management permissions
