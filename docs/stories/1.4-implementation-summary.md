## 🗄️ Database Schema

### `transitions` Table
```sql
ai_planning_enabled BOOLEAN DEFAULT false
```

### `ai_planning_sessions` Table
```sql
CREATE TABLE ai_planning_sessions (
    id UUID PRIMARY KEY,
    session_id VARCHAR(255) UNIQUE NOT NULL,
    transition_id VARCHAR(255) NOT NULL,
    transition_type AITransitionType NOT NULL,
    execution_mode AIExecutionMode NOT NULL,
    status VARCHAR(50) NOT NULL,
    current_step INTEGER DEFAULT 0,
    questions_asked JSONB DEFAULT '[]',
    responses_collected JSONB DEFAULT '[]',
    tasks_generated JSONB DEFAULT '[]',
    milestones_generated JSONB DEFAULT '[]',
    planning_context JSONB,
    created_by VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    completed_at TIMESTAMP,
    FOREIGN KEY (transition_id) REFERENCES transitions(id),
    FOREIGN KEY (created_by) REFERENCES "User"(id)
);
```

## 📝 Lessons Learned

1. **PydanticAI v1.0.17** has different API than documentation
   - Solution: Used placeholder model, implement proper integration when LLM added

2. **Frontend Component Dependencies**
   - Missing `@radix-ui/react-switch` caused blank page
   - Solution: Always check shadcn/ui component dependencies

3. **Test Import Structure**
   - Relative imports failed in tests
   - Solution: Use absolute imports (`from src.module`)

4. **Database Enum Types**
   - PostgreSQL enum types need manual creation before Prisma migration
   - Solution: Create enums in migration SQL

5. **Template Fallbacks Essential**
   - System must work without LLM for reliability
   - Templates provide reasonable defaults
