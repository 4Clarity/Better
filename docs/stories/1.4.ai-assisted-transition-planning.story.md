# Story 1.4: AI-Assisted Transition Planning with Intelligent Task and Milestone Generation

## Status
📝 **Approved** - 10-14-2025

## Story
**As a** Government Program Manager (Brenda),
**I want** an AI assistant to help me plan transition tasks and milestones by asking intelligent questions about scope, scale, and transition type,
**so that** I can quickly create comprehensive, type-specific transition plans with appropriate tasks assigned to the right team roles without manual planning overhead.

## Acceptance Criteria
1. When creating a new transition, system offers AI-assisted planning option
2. AI planning assistant asks contextual questions based on transition type (Contract, Personnel, System)
3. AI assistant collects information about: transition scope, scale, timeline, team composition, risk factors
4. Based on responses, AI generates recommended tasks with:
   - Clear task titles and descriptions
   - Suggested due dates relative to transition timeline
   - Appropriate priority levels
   - Recommended assignee roles (not specific users)
5. AI generates recommended milestones with:
   - Milestone titles and descriptions
   - Target dates aligned with transition phases
   - Status indicators
6. Program Manager can review, edit, accept, or reject AI-generated recommendations
7. Accepted tasks and milestones are created in the database linked to the transition
8. Tasks are assigned to appropriate user roles based on AI recommendations
9. System supports both direct LLM integration and N8N workflow-based planning
10. AI planning history is logged for audit and improvement purposes
11. Planning assistant adapts recommendations based on transition type characteristics
12. All AI interactions follow security and data classification requirements
13. Integration tests verify AI planning workflow end-to-end
14. No regression in existing transition creation functionality

### API Specifications

**Python AI Planning API:**

1. **POST /api/ai-planning/sessions/start**
   - Request: `{ transitionId, transitionType, userId }`
   - Response: `{ sessionId, questions: Question[], status }`
   - Permissions: Program Manager only

2. **POST /api/ai-planning/sessions/:id/respond**
   - Request: `{ responses: { questionId: answer }[] }`
   - Response: `{ sessionId, nextQuestions: Question[], isComplete: boolean }`
   - Permissions: Session creator only

3. **POST /api/ai-planning/sessions/:id/generate**
   - Request: `{ sessionId }`
   - Response: `{ tasks: TaskRecommendation[], milestones: MilestoneRecommendation[] }`
   - Permissions: Session creator only

4. **POST /api/ai-planning/sessions/:id/accept**
   - Request: `{ taskIds: string[], milestoneIds: string[], edits: {} }`
   - Response: `{ success: true, tasksCreated: number, milestonesCreated: number }`
   - Permissions: Session creator only

**Node.js Integration API:**

5. **POST /api/transitions/:id/ai-planning**
   - Wrapper endpoint that orchestrates the full planning flow
   - Handles Python service communication
   - Creates tasks and milestones in database
   - Returns comprehensive results

### Integration Points

**With Ollama (Local LLM):**
- Python service communicates with Ollama via HTTP API
- No data leaves the local network (security requirement)
- Model selection configurable via environment variables
- Fallback to simpler model if primary unavailable

**With Existing Transition System:**
- AI planning is optional enhancement to existing flow
- Manual creation remains fully functional
- AI-generated tasks/milestones use same data models
- Existing task management UI displays AI-generated items identically

**With N8N Workflows:**
- N8N provides alternative orchestration path
- Useful for batch processing or scheduled planning
- Can trigger planning based on transition creation events
- Integrates with notification system for completion alerts

**With Role-Based Access Control:**
- Only Program Managers can initiate AI planning
- Task assignment respects existing role permissions
- AI recommendations map to role names, not specific users
- Security clearance requirements enforced

### Security Considerations

**Data Privacy:**
- No PII or classified data sent to LLM
- Sanitize all user inputs before LLM processing
- Audit log all AI interactions with user ID and timestamp
- Session data encrypted at rest

**Prompt Security:**
- Validate user inputs to prevent prompt injection attacks
- Use structured prompts with clear role definitions
- Limit response length to prevent denial of service
- Implement rate limiting (e.g., 10 planning sessions per user per hour)

**Access Control:**
- AI planning feature gated behind Program Manager role
- Session data scoped to creating user
- Cannot view or modify other users' planning sessions
- Permissions checked at API and database levels

**Compliance:**
- Document AI decision-making process for audit
- Store full planning history (questions, responses, recommendations)
- Allow manual override of all AI recommendations
- Provide explainability for AI suggestions

### UI/UX Guidelines

**AI Interaction Patterns:**
- Conversational tone for questions ("Help me understand...")
- Progressive disclosure (don't overwhelm with all questions at once)
- Clear indication that user is interacting with AI
- Easy way to skip AI planning and use manual mode
- "Why did AI suggest this?" tooltips for recommendations

**Visual Design:**
- Use robot/AI icon to indicate AI-generated content
- Different color scheme for AI suggestions vs. user-created items
- Loading states with meaningful progress messages
- Success states with summary statistics
- Error states with actionable recovery steps

**Accessibility:**
- All AI wizard steps keyboard navigable
- Screen reader support for AI-generated content
- ARIA labels for dynamic content updates
- High contrast mode support

### Error Handling and Fallback

**AI Service Unavailable:**
- Graceful degradation to manual planning mode
- User-friendly error message: "AI assistant temporarily unavailable. You can still create your transition manually."
- Retry mechanism with exponential backoff
- Alert administrators of prolonged outages

**Invalid AI Responses:**
- Validation layer before presenting to user
- Fallback to safe defaults (e.g., standard task templates)
- Log validation failures for model improvement
- Allow user to regenerate recommendations

**Session Timeout:**
- Auto-save session state every 30 seconds
- Resume capability from last saved state
- Warning before session expiration (5-minute countdown)
- Session duration: 30 minutes of inactivity

### Performance Considerations

**Response Time Targets:**
- Question generation: < 2 seconds
- Recommendation generation: < 10 seconds (for 20-30 tasks)
- Acceptance and database persistence: < 1 second

**Optimization Strategies:**
- Cache common question sets by transition type
- Batch task/milestone creation in single transaction
- Use streaming responses for long-running AI operations
- Implement pagination for large recommendation sets

**Load Management:**
- Async processing for AI calls (don't block API)
- Job queue for N8N workflow mode
- Connection pooling for Python ↔ Node communication
- Ollama resource limits to prevent service exhaustion
