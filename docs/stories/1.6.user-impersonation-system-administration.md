# Story 1.6: User Impersonation for System Administration

## Status

Done

## Story

**As a** System Administrator/Demo User,
**I want** the ability to impersonate different user roles through a role selector in the header,
**so that** I can validate workflow navigation, screen visibility, and form functionality across all user types to ensure proper role-based access controls and troubleshoot user experience issues.

## Acceptance Criteria

1. Header displays a role impersonation selector when user has admin privileges or is in demo mode
2. Role selector provides options for all available user roles (Program Manager, Departing Contractor, Incoming Contractor, Security Officer, Observer)
3. Upon role selection, the interface immediately updates to reflect the selected role's permissions and UI visibility
4. Navigation menu items show/hide based on the impersonated role's access permissions
5. Dashboard content updates to display role-appropriate widgets and data views
6. All form fields and buttons respect the impersonated role's permission levels
7. User management features (like user invitation) are only accessible when impersonating authorized roles
8. Clear visual indicator shows which role is currently being impersonated
9. Easy way to return to the original user's role/permissions
10. Impersonation state persists during the session but resets on logout
11. All impersonated actions are logged for audit purposes with original user context

**Request/Response Formats**:
```json

{
  "roleToImpersonate": "Program Manager"
}

// Response
{
  "success": true,
  "impersonatedRole": "Program Manager",
  "originalRole": "System Administrator"
}
```
