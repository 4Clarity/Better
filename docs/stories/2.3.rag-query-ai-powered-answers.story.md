# Story 2.3: RAG Query & AI-Powered Question Answering

## Status

Not Started

## Story

**As a** Government Program Director, Knowledge Manager, or Transition Coordinator,
**I want** to ask questions in natural language and receive AI-generated answers based on the knowledge base documents,
**so that** I can quickly get accurate, contextually relevant information without manually searching through documents, with citations linking back to source material.

## Acceptance Criteria

1. Backend RAG service generates embeddings for user queries
2. Backend RAG service retrieves top-K relevant chunks using vector similarity search
3. Backend RAG service constructs context-aware prompts with retrieved chunks
4. Backend RAG service sends prompts to LLM (Ollama or Gemini) for answer generation
5. RAG query endpoint returns answers with source citations and confidence scores
6. Streaming endpoint provides real-time answer generation with typewriter effect
7. Frontend RAG UI provides chat-style interface for asking questions
8. Frontend displays streaming answers with typewriter effect
9. Frontend shows source citations with links to original document chunks
10. Confidence scores displayed for each answer (0-100%)
11. Query history sidebar shows previous questions and answers
12. Copy answer functionality allows users to copy responses to clipboard
13. Context window management prevents token limit overflow
14. Error handling for LLM service unavailable, timeout, or generation failures
15. Unit tests for RAG service (query pipeline, context construction, citation tracking)
16. Integration tests for complete RAG query workflow
17. E2E Cypress tests for user interaction with RAG chat interface
18. No regression in existing document upload and vector search features

## Agent Parallelization Strategy

### Overview

This story implements advanced RAG (Retrieval-Augmented Generation) capabilities with a focus on **information accuracy, citation transparency, and streaming performance**. The implementation leverages agent parallelization using MCP (Model Context Protocol) servers and follows the proven execution pattern from Story 2.2.1.

**Total Estimated Time:**
- Sequential: 40+ hours (5 days)
- With Parallelization: 16-18 hours (2 days)
- **Time Savings: 60% reduction**

### RAG System Architecture & Information Flow

**RAG Pipeline for Maximum Accuracy & Transparency:**

```
User Query: "What are the key milestones for transition planning?"
    ↓
[PHASE 1: Query Processing & Embedding]
    ↓ Generate query embedding (nomic-embed-text, 768 dims)
    ↓ Validate embedding generation success
    ↓ Log query for audit trail
    ↓
[PHASE 2: Vector Similarity Search]
    ↓ Search pgvector with IVFFlat index
    ↓ Retrieve top-K chunks (default K=5)
    ↓ Filter by similarity threshold (default 0.7)
    ↓ Log retrieved chunks with similarity scores
    ↓
[PHASE 3: Context Construction with Citations]
    ↓ Rerank chunks by semantic completeness
    ↓ Construct numbered context template
    ↓   [1] Doc: "Transition Guide.pdf", Page 3, Similarity: 0.89
    ↓   Content: "The transition planning process..."
    ↓   [2] Doc: "Contract Procedures.docx", Section 2.1, Similarity: 0.85
    ↓   Content: "Critical milestones include..."
    ↓ Track token count (max 4096 for Ollama)
    ↓ Add system prompt with citation instructions
    ↓
[PHASE 4: LLM Generation with Streaming]
    ↓ Send prompt to Ollama (llama3.2) or Gemini (fallback)
    ↓ Stream response chunks via Server-Sent Events (SSE)
    ↓ Parse inline citations [1], [2] in real-time
    ↓ Calculate confidence score (4 factors, 0-100%)
    ↓
[PHASE 5: Response Assembly & Validation]
    ↓ Validate all citations reference valid chunks
    ↓ Calculate confidence: similarity (40%) + coverage (20%) + length (20%) + citations (20%)
    ↓ Assemble response with metadata
    ↓ Log complete transaction for analytics
    ↓
[PHASE 6: Frontend Display]
    ↓ Stream answer with typewriter effect (char-by-char)
    ↓ Display source citations below answer (clickable cards)
    ↓ Show confidence badge (green/yellow/red)
    ↓ Store in query history (localStorage, max 50)
```

**Transparency & Accuracy Enhancements:**

1. **Multi-Factor Confidence Scoring**
   - Similarity scores (40%): Average cosine similarity of retrieved chunks
   - Chunk coverage (20%): Ratio of relevant chunks found vs. query complexity
   - Response completeness (20%): Answer length vs. expected response length
   - Citation coverage (20%): Percentage of retrieved chunks cited in answer

2. **Citation Validation Pipeline**
   - Extract citation numbers using regex: `\[(?:Source\s*)?(\d+)\]`
   - Validate each citation maps to a retrieved chunk
   - Include chunk metadata: document name, page/section, similarity score
   - Generate deep links to original document locations

3. **Hallucination Prevention**
   - System prompt explicitly instructs: "Answer ONLY based on context provided"
   - Fallback response: "I don't have enough information..." when similarity < threshold
   - Citation requirement: LLM must cite sources using [1], [2] format
   - Post-processing: Verify answer doesn't introduce information not in context

```python
# Agent 4 (Confidence Calculator) - Test confidence algorithm
mcp__ide__executeCode(code="""
def calculate_confidence(similarity_scores, num_chunks, query_len, answer_len, citations):
    avg_similarity = sum(similarity_scores) / len(similarity_scores)
    similarity_score = avg_similarity * 40

    chunks_score = min(num_chunks / 5.0, 1.0) * 20

    expected_answer_len = query_len * 3
    length_ratio = min(answer_len / expected_answer_len, 1.0)
    length_score = length_ratio * 20

    citation_ratio = citations / num_chunks
    citation_score = citation_ratio * 20

    total = similarity_score + chunks_score + length_score + citation_score
    return round(total, 2)

# Test scenarios
scenarios = [
    {'sim': [0.9, 0.85, 0.8], 'chunks': 5, 'qlen': 50, 'alen': 200, 'cites': 3, 'expected': 'High'},
    {'sim': [0.7, 0.65, 0.6], 'chunks': 3, 'qlen': 50, 'alen': 100, 'cites': 2, 'expected': 'Medium'},
    {'sim': [0.5, 0.45, 0.4], 'chunks': 2, 'qlen': 50, 'alen': 50, 'cites': 1, 'expected': 'Low'}
]

for s in scenarios:
    conf = calculate_confidence(s['sim'], s['chunks'], s['qlen'], s['alen'], s['cites'])

""")
```

  4. **Attribution (20%)**: Citation coverage ratio

- **Mitigation:** Use polyfill for older browsers (optional)

- **Fallback:** Standard non-streaming endpoint always available
- **Impact:** Minimal - modern browsers support EventSource

- **Mitigation:** Use IDE MCP `getDiagnostics()` after Phase 2 and Phase 3 complete
- **Validation:** Agent 7 must create TypeScript interfaces matching Python Pydantic models
- **Testing:** Integration tests verify request/response format alignment
- **Impact:** If mismatch detected, 1-2 hours to align interfaces

- **Mitigation:** Implement aggressive timeouts (60s max), chunk size limits
- **Testing:** Load testing with concurrent queries (Agent 10)
- **Monitoring:** Track streaming latency and error rates
- **Impact:** If performance issues, tune chunk size or add caching

### RAG Pipeline Architecture

**RAG Query Flow**:

```
User Query: "What are the key milestones for transition planning?"
    ↓
1. Generate Query Embedding (reuse VectorSearchService logic)
    ↓
2. Vector Similarity Search (call VectorSearchService.search())
    → Returns top-5 chunks with similarity scores
    ↓
3. Rerank Chunks by Semantic Boundary Completeness
    → Prioritize chunks marked as "thought-complete"
    ↓
4. Construct Context Prompt
    → System Prompt: "You are a helpful assistant..."
    → Context: "[1] Chunk content... [2] Chunk content..."
    → Query: "What are the key milestones for transition planning?"
    → Instruction: "Answer based on the context above. Cite sources using [1], [2], etc."
    ↓
5. Send to LLM (Ollama llama3.2 via HTTP API)
    ↓
6. Stream LLM Response (Server-Sent Events)
    → event: chunk, data: "The key milestones include..."
    → event: chunk, data: "[1] Planning phase..."
    → event: source, data: { chunk_id: "abc123", document: "Transition Guide.pdf", similarity: 0.89 }
    → event: done, data: { total_tokens: 450, processing_time_ms: 2340 }
    ↓
7. Calculate Confidence Score
    → Factor in similarity scores, citation coverage, response quality
    → Return: 85% confidence
    ↓
8. Frontend Displays Answer with Typewriter Effect
    → Show streaming text character by character
    → Display source citations below answer
    → Show confidence badge (green: 85%)
```

### Server-Sent Events (SSE) Implementation

**Backend (Python FastAPI)**:

```python
from fastapi.responses import StreamingResponse

async def rag_query_stream(request: RAGQueryRequest):
    async def event_generator():
        # Generate query embedding and retrieve chunks
        chunks = await rag_service.retrieve_chunks(request.query)

        # Send source events first
        for chunk in chunks:
            yield f"event: source\n"
            yield f"data: {json.dumps(chunk.to_dict())}\n\n"

        # Stream LLM response
        async for text_chunk in llm_client.generate_streaming(prompt):
            yield f"event: chunk\n"
            yield f"data: {json.dumps({'text': text_chunk})}\n\n"

        # Send done event
        yield f"event: done\n"
        yield f"data: {json.dumps({'total_tokens': 450, 'processing_time_ms': 2340})}\n\n"

    return StreamingResponse(event_generator(), media_type="text/event-stream")
```

**Frontend (React with EventSource)**:

```typescript
const eventSource = new EventSource('/api/knowledge/rag/query/stream', {
  headers: { 'Content-Type': 'application/json' }
});

eventSource.addEventListener('chunk', (event) => {
  const data = JSON.parse(event.data);
  setAnswer(prev => prev + data.text); // Typewriter effect
});

eventSource.addEventListener('source', (event) => {
  const source = JSON.parse(event.data);
  setSources(prev => [...prev, source]);
});

eventSource.addEventListener('done', (event) => {
  const metadata = JSON.parse(event.data);
  setIsLoading(false);
  eventSource.close();
});

eventSource.onerror = (error) => {

  eventSource.close();
};
```

### Context Window Management

**Token Limits**:
- Ollama llama3.2: 4096 tokens (context window)
- Google Gemini: 32,768 tokens (context window)

**Token Counting**:
- Use `tiktoken` library for OpenAI-compatible models
- Approximate: 1 token ≈ 4 characters for English text
- Reserve tokens: System prompt (200), User query (100), LLM response buffer (500)
- Available for context: ~3300 tokens

**Truncation Strategy**:
1. Sort chunks by similarity score (descending)
2. Add chunks one by one, tracking token count
3. Stop when adding next chunk would exceed limit
4. Always include at least 2 chunks (even if over limit slightly)
5. Log warning if context truncated

```python
import re

def extract_citations(answer: str) -> List[int]:
    """Extract citation numbers from answer text."""
    # Match [1], [2], [Source 1], etc.
    pattern = r'\[(?:Source\s*)?(\d+)\]'
    matches = re.findall(pattern, answer)
    return [int(m) for m in matches]
```

### Confidence Score Algorithm

**Calculation Formula**:

```python
def calculate_confidence(
    similarity_scores: List[float],
    num_chunks_retrieved: int,
    query_length: int,
    answer_length: int,
    citations_used: int
) -> float:
    # Factor 1: Average similarity score (0-1) → 0-40 points
    avg_similarity = sum(similarity_scores) / len(similarity_scores)
    similarity_score = avg_similarity * 40

    # Factor 2: Number of relevant chunks (normalized to 0-20 points)
    # More chunks = higher confidence (up to 5 chunks)
    chunks_score = min(num_chunks_retrieved / 5.0, 1.0) * 20

    # Factor 3: Answer length vs query complexity (0-20 points)
    # Complex queries should get longer answers
    expected_answer_length = query_length * 3  # heuristic
    length_ratio = min(answer_length / expected_answer_length, 1.0)
    length_score = length_ratio * 20

    # Factor 4: Citation coverage (0-20 points)
    # Higher if most chunks are cited
    citation_ratio = citations_used / num_chunks_retrieved
    citation_score = citation_ratio * 20

    # Total: 0-100
    total_confidence = similarity_score + chunks_score + length_score + citation_score
    return round(total_confidence, 2)
```

**Confidence Thresholds**:
- **Low** (<50): Red badge, show warning "This answer may not be accurate"
- **Medium** (50-75): Yellow badge, show note "This answer is moderately confident"
- **High** (>75): Green badge, show checkmark "This answer is highly confident"

### Error Handling Patterns

**Error Scenarios**:
1. **No Relevant Chunks Found** (similarity < threshold)
   - Response: "I couldn't find relevant information in the knowledge base to answer your question."
2. **LLM Service Unavailable** (Ollama down)
   - Fallback to Gemini if configured
   - Response: "The AI service is temporarily unavailable. Please try again in a few moments."
3. **LLM Timeout** (response > 60s)
   - Cancel request, return partial answer if available
   - Response: "The request took too long to process. Please try rephrasing your question."
4. **Context Too Large** (tokens > limit)
   - Truncate context, log warning
   - Continue with truncated context
5. **Streaming Connection Lost**
   - Frontend: Show "Connection lost" message, offer retry
   - Backend: Clean up resources, log error
