## Story
**As a** Government Program Director or Program Manager,
**I want** to create, view, edit, and delete Products and Programs with essential operational details,
**so that** I can document and manage the operational objectives, deliverables, and context that define what our Business Operations support.

1. Database schema created with Products/Programs model including essential fields: name, description, objectives, deliverables, dependencies, security classification, and critical dates
2. Backend API provides CRUD endpoints for Products/Programs with proper validation and error handling

4. Frontend provides a form for creating new Products/Programs with all essential fields
5. Frontend provides a form for editing existing Products/Programs with all essential fields
6. Frontend provides detail view showing all information for a single Product/Program
7. Delete functionality includes confirmation dialog and proper cascade handling
8. Role-based access control enforces permissions: Create/Edit (Admin, Gov Program Director, Gov Program Manager), Read (All authenticated users)
9. Form validation prevents submission of incomplete or invalid data
10. Loading states and error messages provide clear user feedback
11. UI follows existing Business Operations section styling and patterns
12. All unit tests pass for backend services and controllers
13. Integration tests verify complete CRUD workflows
14. No regression in existing Business Operations features

### Data Model Design

**ProductProgram Model (Prisma Schema):**
```prisma
model ProductProgram {
  id                     String   @id @default(uuid())
  name                   String   @db.VarChar(200)
  description            String   @db.Text
  objectives             String   @db.Text
  deliverables           String   @db.Text
  dependencies           String?  @db.Text
  securityClassification SecurityClassification
  criticalDates          Json     // Array of {date: string, description: string}

  createdAt              DateTime @default(now())
  updatedAt              DateTime @updatedAt
  createdBy              String
  updatedBy              String

  createdByUser          User     @relation("CreatedProductPrograms", fields: [createdBy], references: [id])
  updatedByUser          User     @relation("UpdatedProductPrograms", fields: [updatedBy], references: [id])

  @@map("product_programs")
}

enum SecurityClassification {
  UNCLASSIFIED
  CUI
  SECRET
  TOP_SECRET
}
```

**Critical Dates JSON Structure:**
```typescript
interface CriticalDate {
  date: string; // ISO 8601 format
  description: string;
  type?: 'milestone' | 'deadline' | 'review' | 'other';
}
```

### API Specifications

**Endpoint Specifications:**

1. **POST /api/business-operations/products-programs**
   - Request Body: `{ name, description, objectives, deliverables, dependencies?, securityClassification, criticalDates }`
   - Response: `{ success: true, data: ProductProgram }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

2. **GET /api/business-operations/products-programs**
   - Query Params: `?page=1&limit=20&search=&securityClassification=`
   - Response: `{ success: true, data: ProductProgram[], pagination: { page, limit, total, pages } }`
   - Permissions: All authenticated users

3. **GET /api/business-operations/products-programs/:id**
   - Response: `{ success: true, data: ProductProgram }`
   - Permissions: All authenticated users

4. **PUT /api/business-operations/products-programs/:id**
   - Request Body: Same as POST (all fields optional for partial updates)
   - Response: `{ success: true, data: ProductProgram }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

5. **DELETE /api/business-operations/products-programs/:id**
   - Response: `{ success: true, message: "Product/Program deleted" }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager
