# Story 4.3: Knowledge Integration and Advanced Features (Tasks, Milestones, Knowledge Links)

## Status
✅ **PRODUCTION READY** - 2025-10-14 (All tests passing, QA approved)

## Story
**As a** Government Program Director or Program Manager,
**I want** to link knowledge documentation to Products/Programs, track internal tasks and milestones, and capture knowledge context,
**so that** I can maintain comprehensive documentation, monitor progress toward deliverables, and provide essential context for knowledge management and transitions.

## Acceptance Criteria
1. Database schema supports tasks as sub-entities of Products/Programs with fields: title, description, status, due date, assigned to
2. Database schema supports milestones as sub-entities of Products/Programs with fields: title, description, target date, status
3. Database schema supports knowledge reference links between Products/Programs and Knowledge Management items
4. Database schema includes knowledge context field on Products/Programs for capturing contextual information
5. Backend API provides CRUD endpoints for tasks within a Product/Program
6. Backend API provides CRUD endpoints for milestones within a Product/Program
7. Backend API provides endpoints to link/unlink knowledge references to/from Products/Programs
8. Frontend displays task list on Product/Program detail page with status indicators
9. Frontend provides UI to create, edit, mark complete, and delete tasks
10. Frontend displays milestone timeline or list on Product/Program detail page
11. Frontend provides UI to create, edit, and delete milestones
12. Frontend displays linked knowledge references with links to Knowledge Management
13. Frontend provides UI to search and link existing knowledge items
14. Frontend displays knowledge context field in editable format
15. Task and milestone completion status visible at a glance (progress indicators)
16. All features respect role-based access control
17. Integration tests verify all knowledge and task/milestone operations
18. No regression in existing Knowledge Management features

### Data Model Design

**ProductProgramTask Model:**
```prisma
model ProductProgramTask {
  id               String              @id @default(uuid())
  productProgramId String
  title            String              @db.VarChar(200)
  description      String?             @db.Text
  status           TaskStatus          @default(TODO)
  dueDate          DateTime?
  assignedTo       String?
  completedAt      DateTime?

  createdAt        DateTime            @default(now())
  updatedAt        DateTime            @updatedAt
  createdBy        String
  updatedBy        String

  productProgram   ProductProgram      @relation(fields: [productProgramId], references: [id], onDelete: Cascade)
  assignedUser     User?               @relation(fields: [assignedTo], references: [id])
  createdByUser    User                @relation("CreatedTasks", fields: [createdBy], references: [id])
  updatedByUser    User                @relation("UpdatedTasks", fields: [updatedBy], references: [id])

  @@map("product_program_tasks")
}

enum TaskStatus {
  TODO
  IN_PROGRESS
  COMPLETED
  CANCELLED
}
```

**ProductProgramMilestone Model:**
```prisma
model ProductProgramMilestone {
  id               String              @id @default(uuid())
  productProgramId String
  title            String              @db.VarChar(200)
  description      String?             @db.Text
  targetDate       DateTime
  status           MilestoneStatus     @default(UPCOMING)
  achievedAt       DateTime?

  createdAt        DateTime            @default(now())
  updatedAt        DateTime            @updatedAt
  createdBy        String
  updatedBy        String

  productProgram   ProductProgram      @relation(fields: [productProgramId], references: [id], onDelete: Cascade)
  createdByUser    User                @relation("CreatedMilestones", fields: [createdBy], references: [id])
  updatedByUser    User                @relation("UpdatedMilestones", fields: [updatedBy], references: [id])

  @@map("product_program_milestones")
}

enum MilestoneStatus {
  UPCOMING
  IN_PROGRESS
  ACHIEVED
  MISSED
  CANCELLED
}
```

**ProductProgramKnowledgeLink Model:**
```prisma
model ProductProgramKnowledgeLink {
  id               String          @id @default(uuid())
  productProgramId String
  knowledgeItemId  String          // Reference to Knowledge Management item
  linkType         String?         @db.VarChar(50) // e.g., "Reference", "Related", "Dependency"
  linkedAt         DateTime        @default(now())
  linkedBy         String

  productProgram   ProductProgram  @relation(fields: [productProgramId], references: [id], onDelete: Cascade)
  linkedByUser     User            @relation(fields: [linkedBy], references: [id])

  @@unique([productProgramId, knowledgeItemId])
  @@map("product_program_knowledge_links")
}
```

### API Specifications

**Task Endpoints:**

1. **POST /api/business-operations/products-programs/:id/tasks**
   - Request: `{ title, description?, status?, dueDate?, assignedTo? }`
   - Response: `{ success: true, data: ProductProgramTask }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

2. **GET /api/business-operations/products-programs/:id/tasks**
   - Response: `{ success: true, data: ProductProgramTask[] }`
   - Permissions: All authenticated users

3. **PUT /api/business-operations/tasks/:taskId**
   - Request: `{ title?, description?, status?, dueDate?, assignedTo? }`
   - Response: `{ success: true, data: ProductProgramTask }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

4. **DELETE /api/business-operations/tasks/:taskId**
   - Response: `{ success: true, message: "Task deleted" }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

5. **PATCH /api/business-operations/tasks/:taskId/complete**
   - Response: `{ success: true, data: ProductProgramTask }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager, assigned user

**Milestone Endpoints:**

6. **POST /api/business-operations/products-programs/:id/milestones**
   - Request: `{ title, description?, targetDate, status? }`
   - Response: `{ success: true, data: ProductProgramMilestone }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

7. **GET /api/business-operations/products-programs/:id/milestones**
   - Response: `{ success: true, data: ProductProgramMilestone[] }`
   - Permissions: All authenticated users

8. **PUT /api/business-operations/milestones/:milestoneId**
   - Request: `{ title?, description?, targetDate?, status? }`
   - Response: `{ success: true, data: ProductProgramMilestone }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

9. **DELETE /api/business-operations/milestones/:milestoneId**
   - Response: `{ success: true, message: "Milestone deleted" }`
   - Permissions: Admin, Gov Program Director, Gov Program Manager

10. **PATCH /api/business-operations/milestones/:milestoneId/achieved**
    - Response: `{ success: true, data: ProductProgramMilestone }`
    - Permissions: Admin, Gov Program Director, Gov Program Manager

**Knowledge Link Endpoints:**

11. **POST /api/business-operations/products-programs/:id/knowledge-links**
    - Request: `{ knowledgeItemId, linkType? }`
    - Response: `{ success: true, data: ProductProgramKnowledgeLink }`
    - Permissions: Admin, Gov Program Director, Gov Program Manager

12. **GET /api/business-operations/products-programs/:id/knowledge-links**
    - Response: `{ success: true, data: ProductProgramKnowledgeLink[] }` (includes knowledge item details)
    - Permissions: All authenticated users

13. **DELETE /api/business-operations/products-programs/:id/knowledge-links/:knowledgeItemId**
    - Response: `{ success: true, message: "Knowledge link removed" }`
    - Permissions: Admin, Gov Program Director, Gov Program Manager

### Integration Points

**With Knowledge Management:**
- Link Products/Programs to knowledge items (documents, articles, references)
- Use existing Knowledge Management API to search and retrieve knowledge items
- Knowledge links should be bidirectional (visible from both sides)
- Ensure existing Knowledge Management features remain functional
- Knowledge context provides additional narrative context beyond links

**With User Management:**
- Task assignment uses existing User model
- Leverage existing user search functionality
- Use user avatars/display components for assigned users

**With Existing Product/Program Features:**
- Tasks and milestones are sub-entities tied to specific Products/Programs
- Deleting a Product/Program cascades to delete tasks, milestones, and knowledge links
- Tasks and milestones contribute to overall Product/Program status

### Security Considerations
- Validate all foreign key references (knowledgeItemId, assignedTo)
- Ensure users cannot link knowledge items they don't have access to
- Audit all task, milestone, and knowledge link operations
- Role-based permissions enforced on backend
- Prevent deletion of tasks/milestones without proper permissions

### UI/UX Guidelines
- Use consistent styling with existing Business Operations section
- Status badges should use color coding:
  - Task TODO: Gray
  - Task IN_PROGRESS: Blue
  - Task COMPLETED: Green
  - Task CANCELLED: Red
  - Milestone UPCOMING: Gray
  - Milestone IN_PROGRESS: Blue

- Timeline view for milestones should be visually appealing (consider using a library like react-chrono)
- Knowledge context editor should support markdown or rich text
- Loading states and error handling for all async operations

- Create migration scripts for tasks, milestones, knowledge links, and knowledge context

- Test migration in development before production
